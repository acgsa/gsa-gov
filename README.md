# GSA.GOV Website

Public-facing informational website for the U.S. General Services Administration, rebuilt on a headless CMS architecture with modular page composition and role-separated editorial workflows.

**Agency:** GSA | **Impact Level:** FIPS Low | **Data Classification:** Public

---

## Architecture Overview

| Component    | Technology                              |
| ------------ | --------------------------------------- |
| Frontend     | Next.js 15 (App Router), TypeScript 5.x |
| Headless CMS | Payload CMS 3.x (Next.js native)        |
| Database     | PostgreSQL 16 (cloud.gov managed)       |
| Hosting      | cloud.gov (FedRAMP Moderate)            |
| CI/CD        | GitHub Actions                          |
| Container    | Docker                                  |

Payload CMS 3.x runs directly inside the Next.js application — there is no separate CMS server. The admin panel is served at `/admin`, and the CMS API is mounted at `/api`.

## Quick Start

### Prerequisites

- Node.js 20+
- Docker and Docker Compose
- Access to `.env` configuration (see `.env.example`)

### Local Development

```bash
# 1. Clone the repo
git clone https://github.com/GSA/gsa-gov.git
cd gsa-gov

# 2. Install dependencies
npm install

# 3. Copy and configure environment
cp .env.example .env
# Edit .env with your local values

# 4. Start PostgreSQL
docker-compose up -d

# 5. Run database migrations
npm run payload:migrate

# 6. Start development server
npm run dev
```

The app is available at `http://localhost:3000`.
The Payload admin panel is at `http://localhost:3000/admin`.

### One-Command Verify

```bash
npm run check
```

Runs lint, type check, and tests in sequence.

## Sandbox Preview (cloud.gov)

A **shareable preview** of the site can be deployed to a personal cloud.gov
sandbox space via the Node.js buildpack. This is a **throwaway preview only** —
public content, no database, no secrets — and sandbox spaces are **wiped every
~90 days**. It is **not** an ATO'd or production environment. See
[ADR-007](docs/decisions/ADR-007-cloudgov-sandbox-preview.md).

```bash
# 1. Log in to your personal sandbox space
cf login -a api.fr.cloud.gov --sso

# 2. Deploy (uses manifest.yml)
cf push

# 3. Point the app at its assigned route, then restage
cf set-env gsa-gov-preview NEXT_PUBLIC_SITE_URL https://<app>.app.cloud.gov
cf restage gsa-gov-preview

# Teardown when finished
cf delete gsa-gov-preview -r
```

The app URL is `https://<app>.app.cloud.gov/` (shown in `cf push` output).

## Content Architecture

Pages are built from **content blocks** (modules). The system enforces role-based access:

| Role            | Can Do                                                      |
| --------------- | ----------------------------------------------------------- |
| **Super Admin** | Create/edit blocks, templates, collections, user management |
| **Editor**      | Create pages from approved templates, edit content, publish |
| **Viewer**      | Read-only access to admin panel                             |

Block definitions live in `src/blocks/` and are controlled exclusively by super admins. Editors assemble pages from approved templates in the admin panel.
